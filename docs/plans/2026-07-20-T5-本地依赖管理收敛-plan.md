# T5 本地依赖管理收敛 plan

**日期：** 2026-07-20
**主线：** T5 工程集成与质量
**设计依据：** `docs/specs/2026-07-20-T5-本地依赖管理收敛-spec.md`
**状态：** 已实施并通过本地验证

## 1. 实施原则

1. 先建立脚本测试和统一接口，再迁移三个 provider，最后删除旧实现。
2. 每一步保持 ONNX Runtime CPU 默认路径可构建，TensorRT 无 SDK 时始终保留明确 stub。
3. 不保留旧变量、旧 Meson option 或兼容分支。
4. managed SDK 的替换必须在临时目录验证完成后原子发布。
5. Meson 只消费 pkg-config；所有 SDK 发现和准备逻辑留在 Bash。
6. 本机不下载、不配置、不链接真实 TensorRT，也不运行 ONNX Runtime GPU。
7. 现有未提交改动属于其他工作，实施时不得回退或覆盖。

## 4. 任务 2：实现公共下载、安装和 pkg-config 契约

改动文件：

- 修改 `scripts/deps/common.sh`
- 修改 `tests/ssv_deps_test.sh`

实施内容：

1. 实现 `curl -fL --retry 3` 与 wget 回退的原子缓存下载。
2. 实现缓存复用、坏缓存删除后最多重下正好一次。
3. 实现 tar、zip 和 deb 公共提取能力；deb 外层使用 ar。
4. 实现 ROOT 相邻同文件系统临时目录和原子替换。
5. 实现非空未知 ROOT 保护和 managed ROOT 安全检查。
6. 实现 pkg-config 标准文件生成辅助函数、版本检查和 `pcfiledir` 来源核对。
7. 实现 system 标准库目录识别、非系统 runtime dirs 收集和去重。
8. 实现统一 C++ 探针编译器选择和执行框架。
9. 保留仓库级 `.deps/build.lock` 覆盖整个准备和构建过程。

验收重点：

- 下载临时文件不会被误当成有效缓存。
- 新安装验证失败时旧 ROOT 保持可用。
- 不创建额外安装元数据文件。
- 不执行哈希校验。

## 5. 任务 3：迁移 ONNX Runtime managed provider

改动文件：

- 新增 `scripts/deps/onnxruntime-managed.sh`
- 修改 `scripts/deps.sh`
- 修改 `tests/ssv_deps_test.sh`

实施内容：

1. 严格解析 `<semver>` 和 `<semver>-gpu`。
2. 根据核心版本、变体和 `x86_64/aarch64` 推导官方 release 归档。
3. 按 `.deps/downloads/onnxruntime/<配置版本>/` 缓存。
4. 在临时 ROOT 解包、生成绝对路径 `onnxruntime.pc`。
5. 校验实际 runtime 版本、头文件、动态库和 pcfiledir。
6. 用 pkg-config 编译并运行最小版本探针。
7. 为 GPU 归档检查运行库可解析性，但不安装 CUDA/cuDNN。
8. 实现统一三行 stdout 协议。

验收重点：

- `1.25.1` 选择 CPU 包。
- `1.25.1-gpu` 选择 GPU 包，pc 版本仍为 `1.25.1`。
- 其他版本格式立即失败。
- 已有匹配 ROOT 时完全离线复用。

## 6. 任务 4：迁移 OpenCV managed provider

改动文件：

- 新增 `scripts/deps/opencv-managed.sh`
- 修改 `scripts/deps.sh`
- 修改 `tests/ssv_deps_test.sh`

实施内容：

1. 将当前 Ubuntu 二进制包名、URL 和内部 revision 映射封装在 provider。
2. 对外只读取 `versions.sh` 的 OpenCV `4.10.0`。
3. 支持 Linux `x86_64/aarch64` 包选择。
4. 用 ar 提取 deb，用 tar 读取 control/data，不依赖 apt 或 `dpkg-deb`。
5. 从 control 校验包名、OpenCV 版本和架构。
6. 准备六个开发/运行模块：core、imgproc、video、calib3d、features2d、flann。
7. 额外准备 dnn 运行时包及其特定 SONAME 的 protobuf 运行库，作为 `libopencv_video` 的实际运行时闭包；不准备 dnn 开发包，也不对外公开 protobuf 链接项。
8. 用 readelf 检查 OpenCV `.so` 的 `DT_NEEDED` 和内部运行时闭包。
9. 生成只链接六个公开模块的规范化 `opencv4.pc`。
10. 使用 pkg-config 编译并运行读取 `cv::getVersionString()` 的最小探针。
11. 实现统一三行 stdout 协议。

验收重点：

- provider 代码之外不出现 Ubuntu revision。
- `opencv4.pc` 不链接 dnn，但运行时能解析 `libopencv_dnn`。
- 缺少宿主通用库时在准备阶段输出明确动态加载错误。
- OpenCV provider 可在没有 `dpkg-deb` 的环境中工作。

## 7. 任务 5：迁移 TensorRT + CUDA managed provider

改动文件：

- 新增 `scripts/deps/tensorrt-managed.sh`
- 修改 `scripts/deps.sh`
- 修改 `tests/ssv_deps_test.sh`

实施内容：

2. auto 无显式材料时只复用现有 ROOT，不触发下载。
3. 支持本地 archive 和可直接下载 URL；URL 采用文件身份缓存。
4. 支持 SDK 直接位于 ROOT 或 ROOT 下单层 `TensorRT-*` 目录。
5. 多个 SDK 候选立即失败。
6. 定位并验证 TensorRT 头文件、版本头、libnvinfer、CUDA 头文件和 libcudart。
7. 从 `NvInferVersion.h` 读取实际版本，不接受人工版本变量。
8. 生成同时表达 TensorRT 与 CUDA Runtime 的规范化 `nvinfer.pc`。
9. 实现统一三行 stdout 协议和真实 SDK 探针代码路径。

本机验收限制：

- 使用 fake 工具覆盖 archive/URL、SDK 布局、版本读取和 pc 生成。
- 实际构建只执行 auto 无 SDK stub 和 disabled。
- 不触发真实 TensorRT 下载、CUDA 探测或后端链接。

改动文件：

使用隔离环境显式选择 system，验证 `pcfiledir` 与最低版本检查。只有本机具备对应系统 SDK 时执行完整构建；否则由 fake pkg-config 测试覆盖发现逻辑。

### 13.5 不执行的本机验证

- 不下载或运行 ONNX Runtime GPU。
- 不下载、配置、链接或运行真实 TensorRT/CUDA。
- 不运行需要 NVIDIA 显卡的模型或性能测试。

## 14. 风险控制

### OpenCV 二进制 ABI 不兼容

通过 readelf 和最小运行探针在原子替换前发现；失败时保留旧 ROOT，并提示使用 system 来源。

### 混合 source 命中错误 pc

在 Meson 前用 `pkg-config --variable=pcfiledir` 核对真实来源；system 依赖被 managed 路径遮蔽时立即失败。

### 构建失败污染运行环境

使用 pending env；只有配置和编译成功才发布成功快照。

### 下载中断或缓存损坏

使用同目录临时下载和原子改名；确认坏缓存后自动删除并重下最多一次。

### 自定义 ROOT 覆盖无关数据

拒绝宽泛路径；非空且无法识别为相同 SDK 时不替换。

### TensorRT 无本机真实验收

通过 fake provider 测试全部配置和准备分支，并通过真实 Meson stub/disabled 构建验证无 SDK 环境；真实 SDK 验证明确不属于本机退出条件。

## 15. 完成判定

实施完成必须同时满足：

1. spec 的全部退出标准成立。
2. 默认 managed 构建、Meson 测试、CLI 测试、依赖脚本测试和 Agent 测试通过。
3. OpenCV disabled 和 TensorRT stub 路径通过。
4. 没有真实 TensorRT 或 ONNX GPU 下载行为。
5. README、`.env.example` 和 CI 与新契约一致。
6. 最终说明明确列出未执行的 GPU 验证及原因。
