# 证据缓存取证竞争保护实施计划

## 步骤 1：在 Agent 取证入口建立输入保护

涉及文件：

- `agent/src/ssv_agent/ssv_cache_evidence.py`

实施内容：

- 保留 finalized 分片选择和 generation/PTS 校验顺序。
- 在创建 ffmpeg concat 清单前，为每个选中 MP4 建立硬链接快照。
- 硬链接跨文件系统失败时复制已 finalized 文件，并把源路径竞争失败转换为可重试的
  `EvidenceExtractionError`。
- 将 concat 清单和 manifest 的输入路径改为临时目录中的受保护路径；保留原分片文件名
  作为输入标识。
- 在现有 `finally` 清理临时目录，确保成功和失败都释放保护引用。

验收：清理源路径不会影响已完成获取的 ffmpeg 输入；获取前源文件消失仍走重试路径。

## 步骤 2：补充竞争场景验证

涉及文件：

- `agent/tests/test_ssv_cache_evidence.py`

实施内容：

- 扩展测试命令 runner，确认 concat 清单中的每个输入在 ffmpeg 调用时存在。
- 模拟首次 ffmpeg 调用前删除源 MP4 和 sidecar，验证硬链接保护仍能完成四个派生证据。
- 强制 `EXDEV` 验证跨文件系统复制分支同样能完成取证。
- 确认临时保护输入不会残留在最终 `derived/<event-id>` 目录。

验收：定向测试覆盖硬链接和复制两条获取路径，并保持既有窗口、generation、路径安全
和幂等测试通过。

## 步骤 3：同步规格和文档边界

涉及文件：

- `docs/specs/2026-09-28-证据缓存取证竞争保护-spec.md`
- `docs/plans/2026-09-28-证据缓存取证竞争保护-plan.md`
- `docs/Agent配置.md`

实施内容：

- 记录 Agent 获取快照、runner 清理继续运行、失败重试和临时磁盘占用语义。
- 在 Agent 配置说明中明确不存在事件豁免；保护发生在取证获取成功之后。

验收：配置文档、规格和实现对清理竞争的时序描述一致。
