# T4 提示词管理模块 Implementation Plan

> **Goal:** 将 Agent 的提示词从硬编码字符串收敛为集中管理的模块——系统提示、策略模板、few-shot 示例、组装器、调试日志、版本管理。

**Architecture:** `prompts/` 包位于 Agent 源码层，独立于状态机和 provider。内容层（system/templates/examples）负责"提示词写什么"，组装层（assembler）负责"怎么拼"，管理层（manager/logger）负责"版本追踪和调用记录"。Provider 通过 `PromptAssembler.assemble()` 获取 messages 列表后直接调用 LLM API，不感知提示词内容。

**Tech Stack:** Python 3.12, dataclasses, structlog。不引入任何新第三方依赖（token 估算用字符数/2）。

---

## File Structure

```
agent/src/ssv_agent/prompts/
├── __init__.py      包入口，导出 PromptAssembler / PromptManager
├── system.py        系统提示词 — 角色定义 + 输出格式 + 行为约束（canonical source）
├── templates.py     策略模板 — 4 种策略各含独立任务模板 + 占位符 + 策略专属系统提示
├── examples.py      Few-shot 示例库 — 标准化示例 + 按标签检索
├── assembler.py     组装器 — 模板 + 示例 + 上下文 → messages 列表 + token 截断
├── logger.py        调试日志 — 记录每次 LLM 调用的完整 prompt 和 response
└── manager.py       轻量管理 — validate() 健康检查 + get_versions() 版本快照
```

- [x] **Step 2: 编写 DEFAULT_SYSTEM_PROMPT**

角色定义："你是工地安全巡检智能 Agent，负责复核安全帽佩戴检测结果。"
判断原则：置信度阈值 >0.85 为高置信度、head+helmet 同时存在按 IoU 判断、track_id 一致的连续检测视为同一目标。
输出格式：JSON `{"is_violation": bool, "reasoning": str, "needs_human": bool}`
行为约束：不编造未提供的信息、不确定时设置 needs_human=true、结论不超过 200 字、引用检测数据时标注置信度。

## Task 4: 组装器 `assembler.py`

**Files:** `agent/src/ssv_agent/prompts/assembler.py`

- [x] **Step 1: 定义 PromptAssembly 和 PromptMessage 数据类**

```python
@dataclass
class PromptMessage:
    role: str      # "system" | "user" | "assistant"
    content: str

@dataclass
class PromptAssembly:
    messages: list[PromptMessage]
    estimated_tokens: int
    template_version: str
    truncated: bool = False
```

- [x] **Step 2: 实现 PromptAssembler 主类**

构造函数：`__init__(max_tokens: int = 4096, max_examples: int = 3, token_ratio: float = 0.5)`

组装流程（`assemble(context, strategy) -> PromptAssembly`）：
1. 渲染系统提示词（`_render_system_prompt()`）
2. 渲染策略模板、填充占位符（`_render_task_template()`）
3. 按标签检索 few-shot 示例、注入为 user/assistant 消息对
4. 构建事件上下文文本（`_build_event_context()`）
5. Token 预算检查与逐级截断
6. 返回 PromptAssembly

- [x] **Step 3: 实现 token 截断策略**

| 优先级 | 裁剪对象 | 动作 |
|:--:|:--|:--|
| 1 | few_shot | N→0 条递减 |
| 2 | 规则片段 | 精简到最相关 1 条 |
| 3 | 检测详情 | 去 bbox 坐标 |
| — | 系统提示/事件标识 | 永不裁剪 |

- [x] **Step 4: 预留 VLM 接口**

`assemble_vlm(context, image_path)` — 抛出 `NotImplementedError`，M5 实现。

**Verification:**
```python
from ssv_agent.prompts.assembler import PromptAssembler
assembler = PromptAssembler(max_tokens=4096)
assembly = assembler.assemble(context, "direct_confirm")
assert len(assembly.messages) >= 1
assert assembly.messages[0].role == "system"
```

## Task 5: 调试日志 `logger.py`

**Files:** `agent/src/ssv_agent/prompts/logger.py`

- [x] **Step 1: 定义 CallRecord 数据类**

```python
@dataclass
class CallRecord:
    call_id: str
    timestamp: str
    strategy: str
    template_version: str
    messages: list[PromptMessage]
    response: str = ""
    parsed_result: dict | None = None
    latency_ms: float = 0.0
    model_name: str = ""
    error: str = ""
    truncated: bool = False
```

- [x] **Step 2: 实现 PromptLogger 类**

`log_call(assembly, response, latency_ms, model_name) -> str` — 记录一次成功调用。
`log_error(assembly, error, latency_ms) -> str` — 记录一次失败调用。
`get_call(call_id) -> CallRecord | None` — 按 ID 检索调用记录。
`enabled` 属性 — 可开关（mock 模式下默认关闭）。

- [x] **Step 3: 日志输出**

使用 `structlog` 将 CallRecord 序列化为结构化日志字段（messages 截断为前 200 字符+总长度）。

**Verification:**
```python
from ssv_agent.prompts.logger import PromptLogger
logger = PromptLogger(enabled=True)
cid = logger.log_call(assembly, "mock response", 150.0, "mock-model")
record = logger.get_call(cid)
assert record is not None
assert record.response == "mock response"
```
