# SSV 短时证据缓存实施计划

## 步骤 1：冻结共享配置和事件锚点

涉及范围：`gst/ssv-common`、`gst/ssv-pub`、`runner/pipeline`、Agent 输入模型。

- 新增 `SsvEvidenceCacheConfig` 和 `evidence_cache` YAML 解析、范围校验及示例配置。
- `ssvpub` 在事件 payload 中发布 `source_pts`、`stream_generation`；保留现有事件字段，
  让 `timestamp_ms` 继续承担发布端墙钟近似时间的兼容语义。
- Agent 取证只使用 SSV cache；启用 `recording_evidence` 时强制要求 cache 开启，
  且缓存目录继续受 `evidence_roots` 约束。
- 补 C++ 配置、拓扑/payload 和 Python 配置测试。

步骤验收：两侧能解析同一配置；旧配置行为不变；事件锚点不会从缺失字段推导。

## 步骤 2：实现 GStreamer 侧缓存模块

涉及文件：

- `runner/pipeline/ssv_evidence_cache.hpp`：新增 `SsvEvidenceCache` 生命周期接口。
- `runner/pipeline/ssv_evidence_cache.cpp`：实现分段命名、sidecar 原子发布、PTS/
  generation 观察、finalize、容量/时间清理和失败隔离。
- `runner/pipeline/ssv_pipeline_topology.hpp`、
  `runner/pipeline/ssv_pipeline_builder.cpp`：增加 encoded tee 和独立缓存分支。
- `runner/pipeline/meson.build`、测试构建文件：加入实现和 focused tests。

核心实现顺序：

1. `h264parse` 后按开关插入 `encoded-tee`。
2. 缓存分支使用有界 `queue` 和 `splitmuxsink`，解码分支保持原有顺序。
3. 在编码分支观察 segment、flush、discontinuity、PTS rollback 和 EOS。
4. 只在 finalized sidecar 发布后允许 Agent 看到该分段。
5. 缓存错误通过独立日志/状态处理，不把可选缓存故障升级为分析主链故障。

步骤验收：拓扑测试通过；构造 H.264 输入能生成可解码分段和 sidecar；缓存关闭、
EOS、重连和清理测试通过。

## 步骤 3：实现 Agent SSV cache 取证

涉及文件：

- `agent/src/ssv_agent/ssv_cache_evidence.py`：新增 sidecar 读取、路径校验、分段
  选择、窗口拼接和派生证据生成。
- `agent/src/ssv_agent/evidence_provider.py`：定义稳定的 `EvidenceExtractor` 接口
  与 extractor 构造边界。
- `agent/src/ssv_agent/service.py`：注入唯一的 `SsvCacheEvidenceExtractor`，不改变
  worker 的 lease/ACK 语义。
- `agent/src/ssv_agent/event_store/ledger.py`：登记派生证据的 PTS 区间和 generation。
- `agent/tests/`：取证接口、服务编排、Ledger 登记和失败降级测试。

步骤验收：SSV cache extractor 能为同 generation 的完整窗口生成四个派生文件；缺少
前置窗口、活跃文件、跨 generation 或路径越界时不会生成误导性证据。

## 步骤 4：文档、验证和迁移

- 更新 `docs/Agent配置.md`、`docs/检测前端配置.md` 和 `docs/roadmap.md`，明确 SSV

  的环境边界。
- 不提交、不推送、不创建 PR；所有步骤完成后保持变更未暂存供人工审阅。

## 兼容和回滚

- 默认 `evidence_cache.enabled: false`，`recording_evidence.enabled` 也默认关闭；
  启用取证时必须同时启用 SSV cache。
- 不提供 MediaMTX 目录回退；关闭 cache 时实时分析仍可运行，但取证 job 会按既有
  失败/人工复核语义处理。
