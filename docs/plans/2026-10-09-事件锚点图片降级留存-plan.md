# 事件锚点图片降级留存实施计划

## 步骤 1：约束与复现

- 用锚点位于 finalized 分段、完整窗口缺失的最小样本复现无图错误。
- 核对完整窗口规格、Worker 重试、账本事务及后续前端所需的证据查询字段。

验证：复现命令在修改前抛出 `evidence cache window is unavailable`；保留独立实测统计。

## 步骤 2：取证器与账本

- 修改 `agent/src/ssv_agent/ssv_cache_evidence.py`，提供只从锚点所在单个有效分段生成图片的路径，保留完整证据路径；按 manifest 校验重试后的已发布产物。
- 修改 `agent/src/ssv_agent/evidence_provider.py`、`agent/src/ssv_agent/workers.py`、`agent/src/ssv_agent/event_store/ledger.py` 和 `agent/src/ssv_agent/event_store/schema.py`，将覆盖范围写入账本，在最后一次缓存窗口失败时登记部分图片并保持人工复核。
- 在 `agent/tests/test_ssv_cache_evidence.py`、`agent/tests/test_workers.py`、`agent/tests/test_event_ledger.py` 以真实调用接口验证完整、部分、失败及重试幂等。

验证：相关 Python 单测、格式与静态检查；最小复现转绿。

## 步骤 3：查询契约与真实流

- 确认 Agent 账本查询投影保留 `coverage`、`event_id` 和 `evidence_id`；后续由独立仓库 `wvp-ssv-web` 消费并显示部分证据状态。
- 用新隔离数据库运行本机 WVP 拉流和 Agent，核对任务、账本记录和图片文件；此步骤不依赖页面或旧 Web API。
- 清理本轮临时 RTSP 配置、探针图片和日志，保留与用户确认相关的运行服务。

验证：账本中的证据类型、覆盖范围和可用状态与实测文件一致；前端 API 和页面验收属于 `wvp-ssv-web` 后续集成。

## 步骤 4：避免缓存尚未完成就耗尽重试

- 修改 `agent/src/ssv_agent/service.py` 的 `AgentService._start_recording_evidence_worker`，将实际 `retry_delay_ms` 与共享缓存的 `segment_duration_ms` 对齐；保留用户配置更长的间隔。
- 修改 `agent/tests/test_service.py`，验证两个配置边界。重新运行相关回归测试。
- 同步 `docs/Agent配置.md` 和 `docs/Agent架构与实现.md` 的现行取证、部分图片和重试语义。
- 修正 `agent/tests/test_evidence_reader.py` 与 `agent/tests/test_evidence_rag_review_integration.py` 中已过期的 `RecordingEvidenceConfig.enabled` 测试夹具，使证据读取回归可执行。

验证：Worker 工厂收到正确的间隔；真实流中继续区分后到达的分段与永远没有有效 PTS 的分段。
