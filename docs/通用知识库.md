# 通用知识入库与向量检索

本模块将一句话、多段文字、Markdown 或 TXT 文件写入独立知识库，通过自然语言查询返回片段正文、相似度和原文位置。不要求规则元数据，不启动事件服务，也不调用聊天模型生成回答。

本文统一记录当前功能、配置、设计约束和验证结论。当前完成知识摄取与检索层，分块采用代码规则，不调用文本生成模型。

## 环境准备

完整项目依赖包含 DeerFlow 子模块。首次克隆后先在仓库根目录运行 `git submodule update --init --recursive`；随后在 `agent` 目录安装现有项目依赖并运行以下命令：

```sh
uv sync
uv run python -m ssv_agent.knowledge_cli --help
```

本机已配置的 `ssv-knowledge` 包装命令和用户目录 Python 环境属于机器环境，不随 Git 提交分发。其他机器使用上述模块入口，或自行配置等价命令；测试文件也可在已安装依赖的解释器中运行。

本地 Qdrant 模式无需启动 Docker。默认数据位于 `agent/data/knowledge_qdrant`；也可以显式传入 `--qdrant-path` 或连接 Qdrant 服务。相对文件路径与显式存储路径按当前工作目录解析。

## 配置真实 Embedding

入库与查询必须使用同一套 Embedding 配置。默认 mock 不具备语义检索能力，本模块拒绝使用。

使用 OpenAI 兼容 Embedding 服务时，在自己的环境文件中配置：

```dotenv
SSV_EMBEDDING_BACKEND=openai_compatible
SSV_EMBEDDING_MODEL=你的向量模型名称
SSV_EMBEDDING_BASE_URL=https://你的服务地址/v1
SSV_EMBEDDING_API_KEY=你的密钥
```

每次调用通过全局参数 `--env-file` 显式加载此文件。已有环境变量优先于环境文件；`--embedding-backend`、`--embedding-model` 和连接参数优先于环境变量。环境文件不提交到仓库。

如果已有本地 BGE-M3 模型，安装 `uv sync --extra bge-m3` 后使用：

```dotenv
SSV_EMBEDDING_BACKEND=bge_m3
SSV_EMBEDDING_MODEL=/本地模型目录
```

BGE 后端只加载本地已有模型，不自动下载。模型、backend 或服务 endpoint 改变后会使用另一套物理 collection，旧向量不会混入新查询，也不会自动迁移；需要使用新配置重新导入。

## 一句话与文件入库

以下命令在 `agent` 目录执行，假设环境文件为 `../.env`。全局参数放在子命令之前。

```sh
uv run python -m ssv_agent.knowledge_cli --env-file ../.env add-text "设备保养手册放在资料室第二层书架。" --source 手工记录
uv run python -m ssv_agent.knowledge_cli --env-file ../.env add-file ../README.md
```

也可以通过标准输入传入长文本：

```sh
cat ../README.md | uv run python -m ssv_agent.knowledge_cli --env-file ../.env add-text --source 项目说明
```

PowerShell 使用 UTF-8 管道：

```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new()
Get-Content -Encoding utf8 -Raw ../README.md | uv run python -X utf8 -m ssv_agent.knowledge_cli --env-file ../.env add-text --source 项目说明
```

成功后输出 JSON，包括 `document_id`、`source`、`chunks_count`、`skipped` 和 `success`。同一来源、规范化正文和处理配置已经成功入库时，`skipped` 为 `true`，不会再次请求 Embedding。

文件支持 `.md`、`.markdown`、`.txt`，先尝试 UTF-8（含 BOM），再尝试 GB18030。文件来源使用绝对路径；换路径导入视为不同来源。正文换行统一为 LF，保留缩进与其他文字。同一来源内容变化会新增文档，旧内容仍可检索；首版没有删除或覆盖更新命令。

## 向量检索

```sh
uv run python -m ssv_agent.knowledge_cli --env-file ../.env search "保养资料在哪里？" --top-k 5
uv run python -m ssv_agent.knowledge_cli --env-file ../.env search "项目如何运行" --min-score 0.5
```

只查询某份文档时加 `--document-id`，值使用入库返回的 ID。检索输出结构为：

```json
{
  "success": true,
  "query": "保养资料在哪里？",
  "chunks": [
    {
      "chunk_id": "片段的稳定哈希",
      "document_id": "文档的稳定哈希",
      "content": "设备保养手册放在资料室第二层书架。",
      "source": "手工记录",
      "chunk_index": 0,
      "content_hash": "sha256:正文哈希",
      "line_start": 1,
      "line_end": 1,
      "heading_path": [],
      "score": 0.8
    }
  ]
}
```

上面的分数仅示意返回结构，实际得分由模型和正文决定。未设置 `--min-score` 时返回最相近的片段，不保证其相关；设置阈值后无达标结果或知识库为空时，`chunks` 为 `[]`。行号从 1 开始，对应规范化全文。

## 分块与存储

默认使用 `markdown` 策略，最多每块 1000 字符，目标重叠 100 字符。先按 `#` 至 `######` 标题识别章节，再沿段落、行和句子边界切分，无标点长文本仍按上限拆分；不同章节不重叠。参数单位是字符，不是 token：

```sh
uv run python -m ssv_agent.knowledge_cli --env-file ../.env add-file ../README.md --chunk-size 800 --chunk-overlap 80
```

无章节短文本只有一个片段，保留完整内容。带标题的短文也可能按章节分成多块。片段的 `heading_path` 记录祖先标题；Embedding 输入会补充最多 256 字符的标题路径，返回的 `content` 仍是原文切片，行号也只指向原文。

能放进一块的围栏代码块、连续列表和表格行尽量保持完整，必要时减少结构附近的重叠；超过长度上限则仍拆分。围栏内的井号不当作章节标题。这里只做轻量结构识别，不实现完整 Markdown 语法树、Setext 标题、渲染、表格语义解析，也不抓取链接或图片。

如需保留上一阶段纯文本切分行为，入库时加 `--chunk-strategy text`；Python 接口使用 `ChunkingConfig(strategy="text")`。默认策略及分块算法版本已更新，旧资料需要重新导入才能获得章节上下文；新旧策略或参数发生变化时重新生成该文档向量并清理旧分块，其他文档不受影响，不会自动重建正式知识库。

### 编号条款与转换文档：structured

对标准条款、编号手册以及带 PDF 页标记的转换 MD，可显式选择 `--chunk-strategy structured`，或在 Python 中使用 `ChunkingConfig(strategy="structured")`。通用默认仍为 `markdown`，旧 `text` 和 `markdown` 的算法身份保留；选择不同策略后需要重新导入。

新策略增加三项处理：

- 识别行首 `4`、`4.1`、`4.1.3`、附录及附录编号，恢复没有 `#` 的章节层级。代码、普通有序列表和表格行不当作条款，图号与表号不替代所属章节。这里只识别行首，不猜测一行中混合的多条条款。
- 在明确带 PDF 页标记的转换资料中，排除目录、索引、重复页首和页附近的页码；排除空图片及通用页图链接。清理只影响模型输入，不改写源文档。普通文档的数字和代码保留，不将前言或参考文献统一丢弃。
- 表格按数据行分块，并补充表名与表头。列数一致且表头可靠时，用“列名：值”生成 Embedding 文本；错列、转义管道、歧义表头等退回原行，不恢复合并单元格，也不猜测缺失字段。超长行仍受原文长度上限约束。

检索的 `content` 仍是原文连续切片，行号对应原文；表格结果可额外包含 `table_name` 和 `table_headers`。内部清理文本不返回到结果，全文记录保留原始规范化内容。标题和表格上下文分别最多额外 256 字符，字段标签也有长度限制；这不是 token 预算。

清理后只剩图片链接等不可检索内容时，返回输入错误，不请求 Embedding。结构识别使用保守文本规则，不等同于完整布局或 Markdown 解析。更细粒度会增加向量数量，适合程度应在自己的问题集上验证。

`ssv_knowledge` 保存向量与片段，`ssv_knowledge_documents` 保存全文、来源、处理配置和完成状态；两者都按模型身份派生实际名称。每批最多向 Embedding 服务发送 20 条文本。解析、Embedding 或向量校验失败不改动已有数据。

远程存储可设置 `SSV_QDRANT_URL`、`SSV_QDRANT_API_KEY`，或使用全局参数 `--qdrant-url`；本地可设置 `SSV_QDRANT_PATH` 或 `--qdrant-path`。显式本地路径会覆盖环境中的远程 URL。与事件服务共享本地路径时仍受 Qdrant 单进程文件锁限制，建议保留独立的默认路径。

## Python 接口

```python
import asyncio
from ssv_agent.knowledge.base import KnowledgeBase

async def main():
    # 提前设置 Embedding 环境变量，或自行加载环境文件。
    with KnowledgeBase() as knowledge:
        result = await knowledge.ingest_text("采购联系人是张工。", source="通讯录")
        hits = await knowledge.search("采购找谁", document_id=result.document_id)
        print(hits)

asyncio.run(main())
```

上下文退出后释放存储连接；不关闭共享或调用方注入的 provider。入库在同一实例中串行执行，首版按单写者使用，同一文档不支持多个实例并发入库。

打开 `agent/tests/test_knowledge_bailian.py`，运行 `test_bailian_flash_retrieves_sentences`。用例直接调用 Python 接口，不通过 CLI；固定使用 `qwen3.7-text-embedding-flash`。

在仓库根目录的本地 `.env` 填写：

```dotenv
SSV_RUN_BAILIAN_TEST=1

SSV_EMBEDDING_API_KEY=你的百炼APIKey
```

`.env` 已被 Git 忽略，密钥不用写进测试代码。配置优先级为进程环境变量、`agent/.env`、仓库根目录 `.env`。缺少开关或凭据时测试显示跳过；接口拒绝请求或首位结果不符合预期时测试失败。

在 VS Code 中选择已安装项目依赖和 pytest 的 Python 解释器，再点击测试函数左侧的运行按钮或测试面板中的对应项目。解释器路径按自己的机器环境配置。

也可以点击 IDE 的“运行 Python 文件”，或直接用 `python test_knowledge_bailian.py` 启动。文件会运行自身的 pytest 用例并显示结果；当前解释器缺少依赖时，自动转到已安装的永久知识库环境，或 Agent 目录的 `.venv`，不需要在全局 Python 中重复安装 pytest。两种环境均不可用时会提示选择已安装测试依赖的解释器，不自动下载或安装软件。

用例会存入设备手册位置与餐厅开放时间，验证重复导入被跳过，关闭并重新打开存储后，用“去哪里找设备的保养资料？”和“午饭几点可以去餐厅吃？”分别检出正确原文。测试输出中可以查看问题、预期原文、候选片段及实际相似度；不固定断言分数，只断言首位原文。

每次正常测试发起四次 Embedding 请求：两次入库、两次查询，重复入库不请求模型。会消耗真实服务额度，费用遵循账号配置；测试数据库位于 pytest 临时目录，不写入正式知识库。关闭 `SSV_RUN_BAILIAN_TEST` 可停止在常规测试中调用真实服务。

### Markdown 检索质量对比

同一测试文件新增 `test_bailian_markdown_retrieval_quality`，可单独点击运行。直接运行整个文件会执行一句话测试和 Markdown 对比两项。样本为 `agent/tests/fixtures/knowledge/handbook.md`，问题和证据标注为同目录 `retrieval_cases.json`，均为虚构测试资料，可阅读并据此建立自己的真实文档测试集。

对比固定使用 160 字符、24 字符重叠、同一个百炼 Flash 模型，以及完全相同的缓存查询向量，分别建立 `text`、`markdown`、`structured` 临时索引。测试输出首位命中率、前三条召回、MRR@3 和逐题排名，再比较 Markdown 与结构化策略的首位原文及章节。MRR@3 对首位正确记 1，第二位记 1/2，第三位记 1/3，前三条未命中记 0。

另有 3 道无答案问题，输出固定诊断阈值 0.5 下的误召回率；该阈值仅用于暴露问题，不修改生产检索默认值，不表示适用于任意模型和文档。相似度高只说明相关，不能保证原文回答了问题。

本样本共 12 道有答案问题和 3 道无答案问题。三策略复用 15 次查询 Embedding，各自批量处理分块；批量请求数随片段数变化。标题和结构分块不能解决所有无答案判断，真实业务效果需要在独立语料上验证，不能将此小样本指标当作通用准确率。

## 错误与边界

命令成功返回退出码 0，执行失败返回 1，并输出 `success: false`、`stage` 和 `error`。`stage` 区分 `input`、`configuration`、`embedding` 和 `storage`；命令语法错误由 argparse 输出帮助并返回 2。

存储写入不是跨操作事务，失败可能留下本次文档部分片段。只有全部写入和清理成功后才标记完成，原命令可重试；重试使用确定性 ID，不反复增加相同片段。失败期间可能检索到部分写入结果，不承诺事务隔离。

PDF、Word、Excel、OCR、图片音视频、问答生成、混合检索和重排均不在首版范围。语义召回质量需要用实际模型和代表性查询验证；测试替身产生的向量仅用于验证数据链路。
