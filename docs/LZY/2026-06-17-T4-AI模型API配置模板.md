## 一、重要说明

真实 API Key 属于敏感信息，不建议提交到 Git 仓库。

建议做法：

1. 本文档只填写模型服务类型、访问地址、模型名、调用方式等非敏感信息。
2. API Key 写入项目根目录 `.env` 文件；`.env` 已在 `.gitignore` 中，不会被 Git 默认提交。
3. 如果为了线下交接临时把 API Key 写入本文档，提交代码或对外发送前必须删除。

## 二、当前 T4 Provider 状态

当前 T4 已经具备完整 Agent 复核编排能力，provider 层目前支持：

| Provider | 状态 | 说明 |
|:--|:--|:--|
| `mock` | 已实现 | 用于单元测试和稳定演示，不调用外部 API |
| `local_yolo` | 已实现 | 读取 `evidence_paths` 关键帧，调用本地 YOLO `.pt` 模型复核 |
| `openai_compatible` | 已实现 | 调用 OpenAI Chat Completions 兼容接口，例如阿里云百炼 DashScope compatible-mode |

外部 AI API provider 接入后，T4 可以把已经构造好的上下文、规则片段、关键帧证据和检测事件发送给真实模型，用于生成更直观的复核解释、风险摘要和汇报文本。

## 四、你只需要填写这里

如果只是为了同步到 `.env` 并跑通外部 AI 版 T4 演示，只需要在本地 `.env` 中维护下面三项。本文档用于提交和交接，不保存真实密钥。

```bash
SSV_AGENT_API_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
DASHSCOPE_API_KEY=<写入本地真实 API Key>
SSV_AGENT_API_KEY=<写入本地真实 API Key>
```

填写说明：

| 配置项 | 怎么填 |
|:--|:--|
| `SSV_AGENT_API_BASE_URL` | 把 `{WorkspaceId}` 换成阿里云百炼业务空间 ID |
| `DASHSCOPE_API_KEY` | 填阿里云百炼 API Key |
| `SSV_AGENT_API_KEY` | 和 `DASHSCOPE_API_KEY` 填同一个 Key 即可 |

本机 `.env` 配好后，可以运行：

```bash
./ssv t4-video-demo \
  --video /home/lzy/work-code/30sec.mp4 \
  --model /home/lzy/work-code/comp-2-freeze10.pt \
  --agent-provider openai_compatible \
  --output-dir output/t4-video-demo-openai
```

## 六、建议写入 `.env` 的配置

项目根目录 `.env` 已被 `.gitignore` 忽略，建议把真实 Key 写在这里。

```bash
# ─── T4 外部 AI Provider（已接入 openai_compatible）──────────────────────
# 是否启用真实外部 AI provider
SSV_AGENT_MOCK_PROVIDER=false

# provider 类型，后续代码可按该值选择实现
# 可选建议：openai_compatible / custom_http / local_yolo
SSV_AGENT_PROVIDER=openai_compatible

# API 访问地址：北京地域示例，必须把 {WorkspaceId} 替换为业务空间 ID
SSV_AGENT_API_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1

# API Key：只写在本地 .env，不提交 Git；两个变量可以填同一个 Key
DASHSCOPE_API_KEY=<写入本地真实 API Key>
SSV_AGENT_API_KEY=<写入本地真实 API Key>

# 文本模型
SSV_AGENT_TEXT_MODEL=qwen3.7-plus

# 多模态模型；按阿里云控制台已开通模型填写
SSV_AGENT_VISION_MODEL=qwen-vl-plus

# 可选参数
SSV_AGENT_API_TIMEOUT_SECONDS=60
SSV_AGENT_API_TEMPERATURE=0.2
SSV_AGENT_API_MAX_TOKENS=2048
```

如果服务需要额外 Header，可以先记录 Header 名称，真实值仍建议写入 `.env`：

```bash
# 示例：仅占位，按实际服务要求调整
SSV_AGENT_API_EXTRA_HEADER_NAME=X-Custom-Auth
SSV_AGENT_API_EXTRA_HEADER_VALUE=<写入本地真实 Header 值>
```

## 七、OpenAI 兼容协议接入方式

阿里云百炼 DashScope compatible-mode 兼容 OpenAI Chat Completions，优先按以下格式接入：

| 字段 | 说明 |
|:--|:--|
| `base_url` | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| `api_key` | 优先从 `.env` 读取 `SSV_AGENT_API_KEY`，也兼容 `DASHSCOPE_API_KEY` |
| `model` | 文本模型使用 `qwen3.7-plus` |
| `messages` | 使用 T4 `ContextEngine` 收集后的系统提示词、事件上下文、规则依据和证据路径组成 |
| `temperature` | `0.2` |
| `max_tokens` | `2048` |

请确认实际请求路径：

```text
POST {SSV_AGENT_API_BASE_URL}/chat/completions
```

请确认鉴权方式：

```text
Authorization: Bearer ${SSV_AGENT_API_KEY}
```

如果鉴权方式不是 Bearer Token，请在“补充说明”中写明。

### Python 连通性验证脚本

在本机 `.env` 写入 `DASHSCOPE_API_KEY` 后，可以用下面脚本验证 API 连通性：

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    base_url="https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1",
)

completion = client.chat.completions.create(
    model="qwen3.7-plus",
    messages=[{"role": "user", "content": "你是谁？"}],
)

print(completion.choices[0].message.content)
```

运行前需要把 `{WorkspaceId}` 替换为实际业务空间 ID。

## 八、如果 API 不兼容 OpenAI 协议

请补充以下信息，便于实现 `custom_http` provider：

| 配置项 | 填写值 |
|:--|:--|
| 请求方法 | `POST / GET / 其他` |
| 完整请求路径 | `按实际服务填写` |
| 鉴权 Header | `填写 Header 名称，不写真实 Key` |
| 请求体 JSON 示例 | `填写脱敏示例` |
| 响应体 JSON 示例 | `填写脱敏示例` |
| 模型输出字段路径 | `例如 choices[0].message.content` |
| 错误码字段路径 | `按实际服务填写` |
| 是否需要流式输出 | `是 / 否` |

脱敏请求示例：

```json
{
  "model": "模型名",
  "messages": [
    {
      "role": "user",
      "content": "请对该安全帽事件进行复核"
    }
  ],
  "temperature": 0.2,
  "max_tokens": 2048
}
```

脱敏响应示例：

```json
{
  "id": "example-response-id",
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "这里是模型返回的复核结论"
      }
    }
  ]
}
```

## 九、T4 接入后的效果

接入真实 AI API 后，T4 汇报演示可以从当前的：

```text
视频检测结果 + 本地 YOLO 复核 + 规则检索
```

升级为：

```text
视频检测结果
  → 关键帧证据
  → T4 上下文构造
  → 规则检索
  → 多模态模型理解关键帧
  → 文本模型生成复核解释、风险摘要和处置建议
  → Redis/JSON 结构化结果回写
```

对上级展示时，可以更直观地说明 T4 完成了以下能力：

| T4 能力项 | 展示方式 |
|:--|:--|
| 事件消费 | Redis Stream 输入 |
| 证据读取 | `evidence_paths` 关键帧 |
| 上下文构造 | 事件、规则、历史、证据统一组装 |
| 工具调用 | `rule_retrieval` 返回规则依据 |
| 模型 provider | 外部 AI API 返回解释性复核结论 |
| 结果回写 | `review.json` 和 Redis review stream |
| 失败降级 | API 不可用时进入 `needs_human` |

### 视频演示命令

`.env` 配置好阿里云百炼 API 后，可以用下面命令让 T4 复核阶段调用 `openai_compatible` provider：

```bash
cd /home/lzy/work-code/ssv-private

./ssv t4-video-demo \
  --video /home/lzy/work-code/30sec.mp4 \
  --model /home/lzy/work-code/comp-2-freeze10.pt \
  --agent-provider openai_compatible \

```

其中 `--model` 仍用于视频抽帧阶段的安全帽 YOLO 检测；`--agent-provider openai_compatible` 表示 T4 Agent 在复核阶段调用外部 AI API 生成解释性结论。
