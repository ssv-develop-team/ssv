# CI 断言兼容性修复规格

## 背景

PR #32 的 GitHub Actions 运行 `39526189074` 在编译 `runner/pipeline/tests/test_ssv_pipeline_plan.cpp` 时失败，五处断言均报 `macro "assert" passed 3 arguments, but takes just 1`。编译停止后，C++ 测试尚未执行，不能将本轮 CI 失败归因于本地已有的动态库缺失或 RTSP 元素链接问题。

这些断言直接比较包含逗号的列表初始化值。预处理器只通过圆括号识别宏参数边界，不通过花括号识别边界，因此单参数 `assert` 将初始化列表中的逗号视为参数分隔符。本机 glibc 2.44 的可变参数 `assert` 掩盖了此问题；将完整测试源文件送入单参数宏语法检查后，能够重现同样的五处错误。

## 目标与范围

- 只修改 `runner/pipeline/tests/test_ssv_pipeline_plan.cpp` 的五处断言，为完整比较表达式增加一层圆括号。
- 保留原有四个测试函数及其断言数量、预期值和失败语义，不删除或弱化断言。
- 涉及 `test_rtsp_hardware_codec_pair_is_bound_to_the_decode_device` 的一处 `SsvVideoCaps` 比较。
- 涉及 `test_rtsp_missing_hardware_encoder_keeps_hardware_decode_as_mixed` 的一处 `SsvVideoCaps` 比较。
- 涉及 `test_rtsp_overlay_forces_system_memory_mixed_path` 的两处 `SsvVideoCaps` 比较。
- 涉及 `test_inference_plan_is_independent_from_codec_plan` 的一处 `std::vector<ssv::SsvProvider>` 比较。

## 接口与生命周期

仅修正测试表达式的宏参数边界，不改变生产类型、函数签名、配置字段、返回值、错误码、资源所有权、生命周期或并发行为。新增文档记录此次兼容性问题的需求、实施范围与验证方式。

## 验收标准

1. 修复前，完整测试源文件使用单参数 `assert` 进行 C++20 语法检查时，重现五处宏参数错误；修复后，同一检查通过。
2. `ssv-pipeline-plan-test` 重新编译成功，`ssv-pipeline-plan` 测试通过。
3. 运行完整 C++ 构建与测试，逐项报告结果；其他失败单独记录，不将部分通过表述为全量通过。
4. `git diff --check` 通过，代码改动仅覆盖五处断言的括号。
5. 本地验证不冒充 GitHub CI 重跑结果；本步完成后保留全部变更为未暂存状态，提交与推送需另行明确指示。

## 非本阶段范围

- 不修改生产管线、推理、证据缓存、Agent 或 Web 行为。
- 不修改 GitHub Actions、构建配置、系统依赖或 lockfile，不关闭断言、不跳过测试。
- 不修复本地已有的 `libhiredis.so.1.3.0` 缺失和 `display-rtp-pay -> display-sink` 链接失败。
- 不修改或清理 `.deer-flow/`，不提交、推送、改写分支历史或合并 PR。
