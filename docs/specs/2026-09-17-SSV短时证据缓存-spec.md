# SSV 短时证据缓存规格

## 背景

当前 Agent 的录像取证依赖外部 MediaMTX 定时录像目录。这个前提在本机部署
MediaMTX 时成立，但从远程 WVP 拉取 RTSP 时，上游视频服务可能不在 SSV 主机上，
因此事件已经进入 Redis 和 SQLite 后，Agent 仍可能找不到事件发生前后的媒体窗口。

SSV 需要拥有一份与实时处理链路同源的短时视频缓存，保证证据获取不依赖某个本机
录像服务。该缓存服务于事件后的近实时取证，不替代 WVP、NVR 或 MediaMTX 的设备
管理、长期录像和历史回放职责。

## 目标

- 在 GStreamer 侧从同一条 RTSP 输入复制一条编码视频缓存分支。
- 优先保留原始 H.264 分段，避免持续解码后再次编码。
- 以 `source_pts` 和 `stream_generation` 精确约束事件与缓存分段的匹配。
- 只让 Agent 读取已经 finalized 且 sidecar 完整的缓存分段。
- 让缓存写盘、清理和索引失败不阻塞检测、跟踪和 Redis 发布主链。
- 启用 Agent 取证时只使用 SSV cache，不再保留 MediaMTX 取证适配器。

## 非本阶段范围

- 不实现长期录像、NVR 索引、历史回放、云端归档或跨设备录像管理。
- 不在 Agent 侧额外建立第二条 RTSP 连接。
- 不把缓存分段直接暴露给模型；模型只能读取 SQLite 已登记的派生证据。
- 不依赖 RTCP/NTP 作为必需条件；它们只作为以后提高墙钟映射精度的增强来源。
- 不跨 `stream_generation` 拼接事件证据。

## 运行边界

```text
RTSP
  -> rtph264depay -> h264parse -> encoded-tee
                                  |-> SSV short evidence cache
                                  `-> decoder -> detection/tracking -> Redis

Redis -> EventConsumer -> SQLite EventLedger -> evidence_extract job
                                            `-> SSV cache extractor
```

WVP/NVR/MediaMTX 负责设备、通道、会话和长期录像；SSV 负责消费 RTSP、实时分析和
最近一段时间的事件证据缓存。两者可以部署在同一主机，也可以完全分离。

## 配置契约

新增共享根配置段 `evidence_cache`：

```yaml
evidence_cache:
  enabled: false
  directory: "/var/lib/ssv/evidence-cache"
  segment_duration_ms: 10000
  retention_ms: 120000
  max_bytes_mb: 512
```

字段语义：

| 字段 | 约束 | 语义 |
| --- | --- | --- |
| `enabled` | 默认 `false` | 是否在 GStreamer 管线创建缓存分支 |
| `directory` | 非空绝对目录 | SSV 与 Agent 共享的缓存根目录 |
| `segment_duration_ms` | 不小于 1000 | 目标分段时长；实际切分受关键帧约束 |
| `retention_ms` | 不小于 `segment_duration_ms` | finalized 分段的最长保留窗口 |
| `max_bytes_mb` | 至少 1 | 缓存根目录的容量上限 |

Agent 不再提供 `agent.recording_evidence.provider` 配置。启用
`agent.recording_evidence` 时，`evidence_cache.enabled` 必须为 true，且
`evidence_cache.directory` 必须位于 `agent.evidence_roots` 允许的绝对根目录内。
这样 Agent 只能从 SSV 产生的共享 cache 取证，缓存目录也不会绕过证据路径的
fail-closed 校验。

## 管线契约

缓存分支位于 `h264parse` 之后、decoder 之前：

```text
h264parse -> encoded-tee -> queue -> splitmuxsink
                         `-> decoder -> clocksync -> decoded-tee
```

- `splitmuxsink` 使用 MP4 容器和原始 H.264，分段切换尽量落在关键帧。
- 缓存分支拥有独立的有界队列；缓存分支不能反压 decoder、分析或发布分支。
- 缓存元素缺失时，只有在 `evidence_cache.enabled` 时报告 capability 错误。
- 缓存写盘异常记录为缓存不可用；检测、跟踪和 Redis 发布保持可运行。
- 活跃分段和没有完整 sidecar 的分段不能被取证 extractor 选中。

## 分段与 sidecar 契约

每个媒体分段 `segment-XXXXXXXX.mp4` 必须配套同名
`segment-XXXXXXXX.json`，sidecar 使用 `ssv.evidence-segment.v1`：

```json
{
  "schema": "ssv.evidence-segment.v1",
  "source": "camera-01",
  "stream_generation": 7,
  "source_pts_start": 123000000000,
  "source_pts_end": 133000000000,
  "wall_clock_start_ms": 1700000000000,
  "wall_clock_end_ms": 1700000010000,
  "media": "segment-00000042.mp4",
  "finalized": true
}
```

约束：

- `source_pts_*` 使用 GStreamer 纳秒时间基；结束值为排他上界。
- `source_pts_start`、`source_pts_end` 或 generation 不可确认时，字段为 null，
  extractor 不得把该分段当作精确 PTS 证据。
- `finalized` 只有在 MP4 文件关闭、sidecar 原子发布并完成基本校验后才为 true。
- sidecar 先写临时文件，再通过同目录 `rename` 发布；extractor 只读取最终文件名。
- 分段属于不同 `stream_generation` 时不得连接成一个证据窗口。
- 清理只删除 finalized 分段和对应 sidecar，不删除当前活跃分段。

## 事件锚点契约

`ssvpub` 发布事件时，在已有字段之外增加：

```json
{
  "source_pts": 123456789000,
  "stream_generation": 7
}
```

这两个字段来自产生该事件的 `SsvTrackedFrame.timing`。`timestamp_ms` 仍表示发布端
墙钟近似时间，不能替代 `source_pts`。事件缺失其中任意字段时，Agent 将对应值保留
为 unknown，不从 `frame_id`、Redis ID 或当前时间反推。

## Agent 取证契约

`SsvCacheEvidenceExtractor` 实现 `extract(EventCase)` 接口，输出一个 clip 和三张帧，
供现有 `RecordingEvidenceWorker` 登记：

- 读取 sidecar，按 source、generation 和 PTS 选择 finalized 分段，再调用 ffmpeg
  生成派生证据。

窗口缺失、generation 不一致、sidecar 不完整或缓存已过期均属于证据不可用，进入既有
失败/人工复核路径，不能解释成“没有目标”。

## 失败与降级

| 情况 | 实时主链 | evidence job |
| --- | --- | --- |
| 缓存关闭 | 正常 | 不创建可用取证证据 |
| `splitmuxsink` 不可用 | 配置启用时启动失败 | 不创建可用缓存能力 |
| 写盘或容量不足 | 继续检测/跟踪/发布 | 重试或进入 `manual_review` |
| 活跃分段未 finalized | 正常 | 延迟重试 |
| PTS 窗口不完整 | 正常 | 延迟重试，最终标记不可用 |
| generation 不一致 | 正常 | 拒绝拼接，标记不可用 |

## 验证要求

- 配置：C++ runner 和 Python Agent 对共享字段使用相同名称、默认值和范围。
- 事件：C++ 发布 payload 测试验证 `source_pts` 和 `stream_generation`。
- 管线：拓扑测试验证 encoded tee、独立 queue 和缓存元素只在启用时出现。
- 分段：测试 finalized 原子发布、窗口选择、generation 隔离、EOS、断流重连和清理。
- Agent：取证 extractor 测试验证 sidecar 缺失、活跃分段、PTS 缺失、路径越界和完整窗口。
- 运行：验证远程 WVP RTSP、断流重连、磁盘满和缓存关闭；MediaMTX 只作为外部长期录像服务，不属于 Agent 取证输入。
