# 模型失败可见性规格

## 1. 背景

当前持久任务只保存 `last_error`，只读 Web API 仅返回任务类型和状态。模型服务调用失败后，页面只能显示笼统的“失败”，无法区分余额、认证、限流、超时、无响应和结果格式错误，也没有失败发生时间。

## 2. 需求

为持久任务增加结构化失败字段，并通过 SSV 只读 API 传递到 `wvp-web-ui`：

- `error_code`：稳定的机器可读错误码。
- `error_message`：脱敏后的用户可读错误说明。
- `failed_at`：失败记录时间，使用 Unix 毫秒时间戳。

API 示例：

```json
{
  "kind": "review",
  "state": "failed",
  "error_code": "model_insufficient_balance",
  "error_message": "模型服务余额不足，请检查模型账户余额。",
  "failed_at": 1792148063426
}
```

字段在没有失败信息、旧数据库缺少新列或任务不是 `failed` 状态时返回 `null`。`last_error` 保留为内部诊断兼容字段，不通过 Web API 暴露。

## 3. 错误分类

模型复核链路至少识别以下稳定错误码：

- `model_insufficient_balance`：上游明确表示余额不足。
- `model_authentication_failed`：凭据无效或认证失败。
- `model_access_denied`：模型服务拒绝访问或权限不足。
- `model_rate_limited`：触发限流或请求过多。
- `model_timeout`：模型调用超时。
- `model_no_response`：模型调用结束但没有可解析输出。
- `model_call_failed`：其他模型调用异常。
- `review_result_invalid`：模型有输出，但不符合复核结果契约。
- `job_failed`：非模型专属的持久任务失败兜底分类。
- `retry_limit_exceeded`：任务在领取前已超过最大重试次数。

无法确认具体上游原因时使用通用错误码，不把完整上游响应、原始请求体、API key、Authorization 或其他凭据写入 `error_message`。原始诊断仍可留在内部 `last_error`，但不得从 API 映射出去。

## 4. 数据与迁移约束

- `durable_jobs` 新增可空列 `error_code TEXT`、`error_message TEXT`、`failed_at_ms INTEGER`。
- 写入失败时更新三列；重试中的任务仍保留数据库诊断，但 API 仅在 `state=failed` 时返回失败字段。
- 成功完成或显式重新入队时清除结构化失败字段。
- 主写入路径执行 SQLite schema migration。
- 只读 API 使用只读连接，不执行迁移；面对没有新列的旧数据库时按能力返回 `null`，不能因查询新列而不可用。

## 5. Web 展示

`wvp-web-ui` 的 `AnalysisTask` DTO、解码器和 `SsvAnalysisTask` 组件支持新字段。失败任务至少展示：

- 失败标签；
- 脱敏后的失败说明；
- 可用时的错误码；
- 可用时的失败时间。

列表页和详情页继续复用同一个任务组件，保持状态展示一致。

## 6. 非本阶段范围

- 不修改模型供应商、模型配置或重试策略。
- 不为历史任务重新发起模型调用。
- 不从历史 `last_error=非法结论: None` 推断原始上游 403 原因。
- 不修改 `.deer-flow/` 或第三方 DeerFlow 源码。
- 不把 `last_error` 变更为 Web 公开字段。

## 7. 验收标准

- 新建数据库和旧数据库迁移后均可读写持久任务。
- 模型余额不足、认证失败、限流、超时、空响应和非法结果分别得到稳定错误码。
- 只读 API 对新旧 schema 均返回合法 `analysis_task`。
- Web 解码器拒绝非法错误字段类型，并能展示失败说明、错误码和失败时间。
- 相关 Python 与 Vitest 测试通过。
