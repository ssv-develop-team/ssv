# CLI 命令边界重构规格

## 目标

将 `./ssv` 的外部基础设施生命周期和 SSV 运行态数据管理分成语义明确的命令，避免使用 `redis` 命令名管理 Qdrant，也避免把 SQLite `EventLedger` 称为普通缓存。

## 接口

基础设施命令：

```bash
./ssv infra start
./ssv infra stop
./ssv infra status
```

这两个命令通过 Docker Compose 管理本地 Redis 和 Qdrant，并等待两个服务就绪。

运行态命令：

```bash
./ssv runtime status
./ssv runtime reset --dry-run
./ssv runtime reset --yes
```

`runtime status` 读取 Redis Stream、consumer group pending、去重键和 SQLite `EventLedger` 状态。`runtime reset --dry-run` 只统计、不修改；实际重置必须显式提供 `--yes`，会删除当前运行配置对应的 Redis 运行态记录和 SQLite 运行态表。

## 约束

- 不再注册或保留 `./ssv redis`、`./ssv cache` 命令入口。
- `infra` 只管理外部服务进程，不清理业务数据。
- `runtime` 不负责启动或停止 Docker 容器。
- Redis 与 SQLite 清理仍然分别执行，任一存储失败都返回非零状态并报告部分结果。
- 不改变 Redis key、Stream、consumer group、SQLite schema、Qdrant volume 或现有配置键。
- 历史 spec/plan 保留原有命令事实；只更新当前使用文档和测试。

## 非本阶段范围

- 不新增单独的 Qdrant 索引构建命令。
- 不改变 Agent、runner、Web API 或 RAG 检索行为。
- 不迁移已有运行数据，不自动执行 `runtime reset`。
