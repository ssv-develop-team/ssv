# 事件锚点图片降级留存规格

## 背景

本机 WVP 设备 `35020000001320000001` 的实测中，事件已经进入账本，但短时缓存分段存在 PTS 间隙、代际变化和无法确定时间的分段。一次 94 条事件的运行中，19 个取证任务生成完整证据，75 个任务因 `evidence cache window is unavailable` 耗尽重试，因此这些事件没有可供结果查看端呈现的图片。另一轮 55 条 Redis 事件中，26 条的锚点落在同代际有效分段内，但只有少数事件满足完整前后窗口。

已有精确窗口要求仍然有效：完整证据只由同代际、连续覆盖冻结窗口的 finalized 分段生成。不能把缩短窗口、跨代际片段或存在较大时间间隙的片段标记为完整证据。

## 目标

- 完整窗口优先，保留现有一个 clip、三张图片和后续复核任务的成功语义。
- 完整窗口因缓存不可用而耗尽重试时，若事件 `source_pts` 落在同源、同代际、带有效时间元数据的 finalized 分段内，尝试生成一张锚点附近图片。
- 单图在账本中明确标记为 `anchor_only`，事件保持 `manual_review`，不创建自动 review 任务；后续 `wvp-ssv-web` 展示图片时应写明“锚点附近图片（部分证据）”。
- 若锚点分段或图片不可用，保持现有失败和人工复核路径，不登记虚假的图片。

## 契约

- `EvidenceArtifact.coverage` 与 SQLite `evidence.coverage` 取 `exact_window`、`anchor_only`、`unknown`。完整取证为 `exact_window`；旧数据和其它来源证据默认为 `unknown`。后续面向前端的查询 API 契约应返回该字段；API 所属服务和部署方式在 Web 集成阶段确认。
- `anchor_only` 仅用于 `kind=frame`，并在 manifest 中记录 `time_basis=source_pts_anchor`、事件请求锚点、分段真实 PTS 范围和媒体输入。账本登记前仍校验文件位于允许根目录内、大小、mtime 和 SHA-256。
- 锚点图片的 `source_pts_start`/`source_pts_end` 记录来源分段的 PTS 范围；它表示可验证的来源范围，不声称图片恰好对应某一纳秒。请求锚点另由 manifest 记录。
- 取证器不使用无 PTS sidecar、活跃分段或其它代际分段。图片抽取以单个已固定的媒体分段为输入，避免 concat 折叠媒体间隙。
- 完整取证重试耗尽时，Worker 才调用可选的锚点图片能力；其它 extractor 保持既有完整取证接口。降级成功时，账本在同一事务中登记图片、完成 extract job 并把事件置为 `manual_review`；不创建 review job。Lease 校验和幂等规则保持不变。
- Agent 启动取证 Worker 时使用 `max(recording_evidence.retry_delay_ms, evidence_cache.segment_duration_ms)` 作为实际重试间隔，避免 segment 尚未 finalized 就过早耗尽重试；显式设置更长间隔仍生效。此项不改变任务首次可领取时间和最大尝试次数。
- 已进入 `dead` 的历史 job 不自动回填；源缓存已清理时也无法重新生成精确图片。

## 非本阶段范围

- 不放宽完整证据窗口的 PTS 连续性要求，也不拼接不连续分段。
- 不接入视频预览、第二条 RTSP 连接或推断缺失的 `source_pts`。
- 不把部分图片用于自动模型结论；人工复核状态由用户识别。
- 不保证在锚点本身没有有效缓存分段时生成图片。该场景需要检测帧直出或缓存链路修复，另行设计。

## 验收

1. 完整窗口仍返回 clip 与三图，并触发 review。
2. 锚点可用而完整窗口不全时，重试耗尽后仅登记一图，标记 `anchor_only`，事件为 `manual_review`，无 review job。
3. 锚点分段缺失、代际不符、元数据无效、路径不安全或抽帧失败时，不登记证据。
4. 账本可查询到 `coverage=anchor_only` 和已登记图片；后续 `wvp-ssv-web` 集成应在详情中明确说明图片为部分证据。
5. 真实 WVP 拉流再次验证，并分别报告完整、部分和无证据事件数量。
6. 分段时长超过配置重试间隔时，Worker 的实际重试间隔不小于分段时长。
