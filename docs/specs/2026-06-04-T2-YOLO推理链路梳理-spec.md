# T2 YOLO 推理链路梳理 Spec

## 背景

`M1` 任务包 A 属于 `T2` 感知算法与元数据主线，目标是基于现有 `gst/ssv-infer` 实现梳理 YOLO ONNX 推理链路。本文档只描述当前工程行为和本任务包交付边界，不修改 `ssv_meta` 字段契约、训练产物契约、Redis 事件 schema 或运行脚本接口。

## 目标

1. 明确 `ssvinfer` 从 GStreamer `BGR` 视频帧到 `SsvFrameDetections` 的处理步骤。
2. 说明 ONNX Runtime 加载、输入张量构造、letterbox、CHW 排布、置信度过滤、类别过滤和 NMS 的当前实现。
3. 标注当前支持的模型输出格式和限制，供 `M1` 后续任务包 B、C、D 继续冻结接口和验证链路。

## 范围

本阶段范围：

- 分析 `gst/ssv-infer/gstssvinfer.cpp` 中的真实推理链路和 `mock-detect` 降级链路。
- 新增中文链路说明文档，覆盖输入、预处理、推理、后处理、输出元数据和限制。
- 使用现有构建与测试命令作为验收：`./ssv build`、`meson test -C build`。

非本阶段范围：

- 不修改 C++ 推理行为。
- 不新增安全帽类别、label map 或训练命令。
- 不冻结 `SsvDetection` 坐标字段契约细节，该内容由 `M1` 任务包 B 处理。
- 不新增真实模型 smoke 脚本，该内容由 `M1` 任务包 D 处理。
- 不接入 Agent、Redis 事件判定或证据输出。

## 当前接口

### 插件属性

`ssvinfer` 当前暴露以下基础属性：

| 属性 | 默认值 | 当前语义 |
| --- | --- | --- |
| `model-path` | 空 | YOLO ONNX 模型路径；真实推理模式下必须设置 |
| `conf-threshold` | `0.5` | 后处理阶段的最小类别置信度 |
| `target-class` | `person` | 只输出指定 COCO 类别；空字符串表示不过滤类别 |
| `mock-detect` | `false` | 跳过模型加载并生成固定 `person` 检测 |
| `async` | `true` | 后台线程只处理最新帧，实时链路不等待每帧推理完成 |

### GStreamer caps

`ssvinfer` sink/src pad 只声明 `video/x-raw, format=BGR`。上游需要在进入插件前完成颜色空间转换。

### 输出元数据

真实推理和 mock 推理都写入 `SsvDetectionStore::instance()`，数据类型为 `SsvFrameDetections`。当前 `source_id` 固定为 `pipeline-0`，`frame_id` 由插件内递增。

## 推理链路要求

### ONNX Runtime 加载

真实推理模式下，`start` 阶段创建 `Ort::Env`、`Ort::SessionOptions`、`Ort::Session` 和 CPU `Ort::MemoryInfo`。当前设置 `SetIntraOpNumThreads(1)`，启用 `ORT_ENABLE_ALL` 图优化，并读取第一个输入和第一个输出名称。

模型输入形状按 `NCHW` 读取，`model_h` 使用输入 shape 的第 3 维，`model_w` 使用第 4 维。输出 shape 为三维时，代码用 `dim1 < dim2` 判定为 YOLOv8 格式，并设置 `num_classes = dim1 - 4`；否则仅识别为 YOLOv5 形状，但当前没有 YOLOv5 后处理输出分支。

### BGR 输入和 letterbox

插件从当前 negotiated caps 获取 `GstVideoInfo`，映射 `GstVideoFrame` 后读取 BGR 平面数据、宽高和 stride。预处理函数按模型输入尺寸计算等比缩放比例，将源图缩放到模型输入内，并用 `114 / 255` 填充 padding 区域。

### CHW 张量

预处理输出为 `float32` 张量，形状为 `[1, 3, model_h, model_w]`。输入源是 BGR 字节序，但写入张量时转换为 `RGB` 通道顺序和 `CHW` 布局，数值归一化到 `[0, 1]`。

### YOLOv8 后处理

当前只对 `is_yolov8 == true` 且运行时输出 shape 为三维的结果调用 `parse_yolov8`。解析逻辑假设输出排布为 `[1, 4 + num_classes, n_anchors]`，每个 anchor 读取 `cx, cy, w, h` 和各类别分数。

后处理顺序如下：

1. 对每个 anchor 选择最高类别分数作为 `confidence`。
2. 使用 `conf-threshold` 丢弃低置信度候选。
3. 将 `target-class` 转为 COCO 类别索引；索引有效时只保留该类别。
4. 将 box 从中心点格式转为 `x1, y1, x2, y2`。
5. 若输出坐标看起来是像素坐标，则按 letterbox 的 scale 和 padding 回映射到原图归一化坐标。
6. 将坐标 clamp 到 `[0, 1]`，丢弃无效框。
7. 按类别内 IoU 执行 NMS，IoU 阈值固定为 `0.45`，最多保留 `50` 个检测。

### 类别命名

`target-class` 和 `class_name` 当前基于内置 COCO 80 类名称表。非 COCO 类别会写为 `class_<id>`，但 `target-class` 不能按自定义 label map 名称过滤。

## 错误处理

- `mock-detect=true` 时跳过模型加载。
- 真实推理模式下 `model-path` 为空会使插件启动失败。
- ONNX Runtime 加载异常会记录错误并启动失败。
- 单帧推理异常会记录 warning，并写入空检测结果，不中断 pipeline。
- 无法读取 caps 或无法映射视频帧时写入空检测结果。
- `async=true` 时使用 latest-frame 队列，旧帧可能被新帧覆盖。

## 验证方式

本任务包验收使用：

```bash
./ssv build
meson test -C build
```

其中 `meson test -C build` 覆盖插件注册、基础 overlay 行为和 `SsvDetectionStore` 基本流转。真实模型推理 smoke 不在任务包 A 范围内。
