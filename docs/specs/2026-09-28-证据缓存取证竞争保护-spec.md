# 证据缓存取证竞争保护规格

## 背景

SSV runner 会在 finalized 分片产生后，按保留时间和容量清理连续缓存。Agent 的取证
worker 可能同时读取同一批分片；如果清理先删除源路径，ffmpeg 可能在取证中途失去输入。
事件进入 SQLite 或创建 evidence extract job 不会自动延长缓存分片的生命周期。

## 目标

- Agent 在开始媒体处理前获取事件窗口所需的全部 finalized 分片。
- 获取成功后，取证使用 Agent 临时目录中的受保护输入，runner 可以继续清理原缓存路径。
- 获取期间发生清理时，产出的 clip 和帧仍来自同一批完整分片。
- 获取前分片已经消失时，保持现有可重试失败和 `manual_review` 语义。
- 不改变 runner 的缓存清理策略，不增加跨进程数据库锁或事件豁免状态。

## 非本阶段范围

- 不让 runner 查询 SQLite 事件、episode 或 durable job 来决定是否清理。
- 不把整个缓存目录永久复制为长期录像。
- 不改变 finalized sidecar、PTS、stream generation 和证据窗口契约。
- 不改变 evidence extract worker 的 lease、重试次数和 ACK 语义。

## 获取契约

取证流程按以下顺序执行：

```text
读取并校验 finalized sidecar
  -> 选择覆盖完整 PTS 窗口且 generation 一致的分片
  -> 在事件临时目录获取全部 MP4 输入
  -> 仅使用临时目录中的路径生成 concat 清单
  -> ffmpeg 生成 context.mp4 和三张帧
  -> 写 manifest 并原子发布 derived/<event-id>/
```

获取 MP4 时优先建立硬链接。硬链接建立后，即使 runner 从缓存目录解除原文件名，
文件 inode 仍由 Agent 临时目录持有，ffmpeg 可以继续读取。缓存根目录和 Agent 输出根目录
位于不同文件系统时，改为复制已 finalized 的 MP4；复制使用已打开的源文件，源路径随后
被删除不会截断已打开的读取。硬链接或复制失败都不会发布部分证据。

sidecar 仍只在源缓存目录中读取。它在分片选择阶段提供 source、PTS 和 generation；
选择完成后这些元数据保存在内存中，清理 sidecar 不会影响已获取的 MP4 输入。

## 并发语义

| 清理时机 | Agent 行为 | 结果 |
| --- | --- | --- |
| 选择前删除 | 找不到完整窗口 | 可重试；重试耗尽后 `manual_review` |
| 选择后、获取前删除 | 硬链接/复制失败 | 可重试；不发布派生证据 |
| 获取完成后删除 | 临时输入仍存在 | 继续完成 ffmpeg 和 manifest |
| ffmpeg 运行中删除 | 临时输入仍存在 | 当前取证继续，不依赖源路径 |
| sidecar 在读取前消失 | 分片不再满足 finalized 选择 | 可重试 |
| sidecar 在选择后消失 | MP4 已被获取，元数据已保留 | 当前取证继续 |

临时输入只在 `extract` 调用期间存在，成功或失败都会在 `finally` 中删除。临时硬链接
持有期间，缓存清理统计只看源目录；因此短时间内实际磁盘占用可能高于缓存容量上限，
待取证结束释放链接后恢复。

## 安全与完整性

- 获取目标必须位于 Agent 已校验的 derived 临时目录。
- 源缓存文件仍拒绝 symlink 和非普通文件。
- concat 清单只写临时输入路径，不能回退到已选中的源路径。
- 失败时不登记 evidence 引用；既有 worker 负责重试或转人工复核。

## 验收标准

- runner 在 Agent 获取完成后删除原 MP4 和 sidecar，Agent 仍能完成一个完整四文件证据集。
- 同文件系统使用硬链接路径；跨文件系统强制复制时也能完成同一场景。
- 获取前源分片缺失时，取证保持可重试错误。
- 派生目录只保留 `context.mp4`、三张 JPEG 和 `manifest.json`，不保留临时输入。
