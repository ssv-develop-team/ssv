# 事件规则发布契约实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让新检测事件在进入 Redis 时携带完整登记规则，使 Agent 能结合证据和 RAG 条款完成可追溯复验。

**Architecture:** 在现有 `SsvSourceConfig -> pipeline builder -> ssvpub` 发布链路中增加 source 级 `event_rule` 配置。`ssvpub` 复用已有 nlohmann JSON payload 构造，将规则字段写入消息；Python Agent 不新增规则映射，继续从 Redis payload 构造 `ReviewContext`。

**Tech Stack:** C++17、yaml-cpp、nlohmann JSON、GStreamer、Redis Streams、Python 3.12、pytest、Meson。

**Spec:** [2026-09-09-事件规则发布契约-spec.md](../specs/2026-09-09-事件规则发布契约-spec.md)

## Global Constraints

- 保留当前工作区已有 staged、unstaged 和 untracked 用户修改，不执行 reset、checkout 或覆盖全文件。
- 能复用现有 payload、配置解析、pipeline 注入和 Agent 字段代码时直接扩展，不建立重复的 Agent 规则功能。
- 每个实现步骤先写失败测试并确认失败，再写最小生产代码。
- 每个步骤完成后保持该步骤变更未暂存，不提交、不推送、不创建 PR。
- 不修改 `agent/third_party/deer-flow`。
- `event_rule` 缺失或非法时，C++ runner 配置加载失败；旧 Redis/SQLite 数据不回填。

## 文件与职责映射

- `gst/ssv-common/include/ssv_config.hpp`：新增 `SsvEventRuleConfig` 及 source 配置成员。
- `gst/ssv-common/config/ssv_config.cpp`：解析、转换和严格校验 `sources[].event_rule`。
- `gst/ssv-common/meson.build`：为配置解析复用 nlohmann JSON 依赖。
- `gst/ssv-pub/gstssvpub.hpp`：声明带发布规则的 payload 接口。
- `gst/ssv-pub/gstssvpub.cpp`：持有规则属性并序列化 Redis payload。
- `runner/pipeline/ssv_pipeline_builder.cpp`：把 source 规则配置传入 `ssvpub`。
- `config/ssv.yaml`、`config/ssv.example.yaml`：补充真实和示例 source 规则配置。
- `gst/ssv-common/tests/test_ssv_config.cpp`：覆盖规则配置成功与失败校验。
- `gst/tests/test_ssv_pub_payload.cpp`：覆盖规则 payload 序列化。
- `runner/pipeline/tests/test_ssv_pipeline_builder.cpp`：覆盖 publisher 规则属性注入。
- `docs/检测前端配置.md`：记录 source 规则配置和发布语义。
